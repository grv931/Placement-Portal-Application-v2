## Overview

The Placement Portal Application is a web-based system designed to manage the campus placement process efficiently. The platform connects three types of users: Admin (Placement Cell), Companies, and Students.

The system allows companies to register and create placement drives, students to apply for these drives, and administrators to monitor and control the entire recruitment workflow.

The V2 update transitions the project from a monolithic Jinja2 application to a modern decoupled architecture, introducing a RESTful API backend, an asynchronous task queue, and a reactive frontend.

---

## Objectives of the Project

The main objective of this project is to digitize the placement process and reduce manual coordination between students, companies, and the placement cell.

The system provides:

- A centralized platform for placement activities
- Secure, token-based authentication for different user roles
- Company approval management
- Placement drive management
- Student application tracking
- Selection status management
- Automated background jobs for reporting and notifications

## Technologies Used

The application is developed using the following frameworks and libraries:

### Backend

- Flask - Python web framework used to build the REST API
- SQLAlchemy - ORM used for database interactions
- SQLite - Lightweight relational database
- Werkzeug - Used for password hashing
- Flask-JWT-Extended - Used for secure, stateless JSON Web Token authentication
- Celery - Asynchronous task queue for background jobs
- Redis - Message broker for Celery and in-memory cache
- Flask-Caching - Used to cache heavy database queries
- Flask-Mail - Used for sending automated email notifications

### Frontend

- HTML5
- Vue.js 3 - Reactive JavaScript framework (CDN setup)
- Bootstrap 5 - For responsive UI components
- Vanilla JavaScript - For API communication and DOM manipulation

---

## System Architecture

The application follows a decoupled client-server architecture. The frontend is a Single Page Application (SPA) that communicates with the Flask backend via a REST API.

### User Roles

1. Admin (Placement Cell)
2. Company
3. Student

Each role has a separate dashboard and strict role-based access control (RBAC).

---

## Features

### 1. Student Functionalities

Students can:

- Register an account
- Upload their resume
- Manage their academic profile
- View available placement drives
- Apply to placement drives
- Track their application status (Applied -> Shortlisted -> Interview -> Placed)
- Request an asynchronous CSV export of their application history

Additional restriction:

- Blacklisted students cannot apply for placement drives

---

### 2. Company Functionalities

Companies can:

- Register on the platform
- Wait for admin approval
- Create placement drives
- Edit or delete drives
- View student applications
- Update hiring status and schedule interview dates
- Trigger a background task to export applicant data as a CSV

Important rule:

- Companies can only access the dashboard after admin approval

---

### 3. Admin Functionalities

Admin acts as the Placement Cell authority.

Admin can:

- Approve or reject company registrations
- View all registered students
- View all companies
- Blacklist or unblacklist students
- Approve or reject placement drives
- Monitor platform statistics via a high-performance cached dashboard
- Receive automated monthly placement reports generated by Celery Beat

---

## Database Design

The application database contains the following main entities:

### Tables

1. User (handles authentication and roles)
2. StudentProfile
3. CompanyProfile
4. PlacementDrive
5. Application

### Relationships

- A Company can create multiple Placement Drives
- A Student can apply to multiple Placement Drives
- Each application stores the selection status and historical state transitions

---

## API Endpoints

The backend exposes over 20 REST API endpoints.

### Core Endpoints

| Endpoint | Method | Description |
|---|---|---|
| /api/auth/login | POST | Authenticates user and returns JWT token |
| /api/student/apply/<drive_id> | POST | Submits application and updates relationships |
| /api/company/application/<app_id>/status | POST | Updates hiring status and logs historical transitions |
| /api/student/export-history | POST | Triggers an asynchronous Celery task to generate CSV |

### Additional Resources

- **Admin**: Endpoints for fetching aggregated statistics (Cached via Redis) and managing user/company states.
- **Company**: Endpoints for creating placement drives and fetching applicants.
- **Student**: Endpoints for profile updates and fetching available placement drives.

## Security and Performance Features

The system includes the following advanced features:

- Password hashing using Werkzeug
- Stateless authentication using JWT
- Role-based route protection
- API route caching using Redis to reduce SQLite load times
- Background task offloading for heavy operations (CSV generation, Emails)

## How to Run the Project

Running the project requires four separate terminal processes in Windows.

1. Start the Redis Server (in WSL terminal)

   ```
   sudo apt install redis-server
   sudo service redis-server start
   redis-cli ping
   ```

2. Start the Flask Backend (in PowerShell 1)

   ```
   cd backend
   python -m venv venv
   venv\Scripts\activate
   pip install -r requirements.txt
   python app.py
   ```

3. Start the Celery Worker (in PowerShell 2)

   ```
   cd backend
   venv\Scripts\activate
   celery -A app.celery worker --loglevel=info -P solo
   ```

4. Start the Celery Beat Scheduler (in Powwershell 3)

   ```
   cd backend
   venv\Scripts\activate   
   celery -A app.celery beat --loglevel=info
   ```

5. Start the Frontend (in Powershell 4)

   ```
   cd frontend
   python -m http.server 8000
   ```

6. Open the application in the browser at [http://localhost:8000](http://localhost:8000)
